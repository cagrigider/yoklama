## Project Overview

Yoklama is a local-only meeting attendance app for one AI Champion and one group. There is no login and no hosted service. Champions clone the private GitHub repo, run it on their machine, and keep their roster and marks in a local SQLite file that is not pushed.

## Build & Run

There is no compile or package step. Syntax-check with `python3 -m py_compile app.py`, then run `python3 app.py` and open http://127.0.0.1:8765. Python 3 standard library is enough — no pip, no `package.json`. Exact commands live in `.factory/build-profile.md`. Tests are not in the tree yet; when they exist, use pytest or unittest against an isolated temp database, never the operator’s `data/attendance.db`.

## Module Architecture

A single process: `app.py` is a `ThreadingHTTPServer` on loopback that serves JSON under `/api/*` and static files from `static/` (hash-router SPA: meetings, people, live roster). Persistence is SQLite at `data/attendance.db`. Optional first roster is `seed/people.json` (gitignored); `seed/people.example.json` is the tracked synthetic example. Architecture memory and ADRs are owned by the architect (`.factory/ARCHITECTURE.md`, `docs/adr/`).

## Technology Stack

Python 3 (stdlib: `http.server`, `sqlite3`, `json`, `pathlib`) plus vanilla JavaScript, HTML, and CSS. Product UI copy is Turkish. GitHub remote: `cagrigider/yoklama`, branch `main`.

## Configuration

(`project-profile.md` plus the per-agent profiles), not here. Run `/factory:initialize` to regenerate them.

**External tooling.** Jira, Confluence, Azure DevOps, GitHub, GitLab, and Bitbucket are reached through adFactory's **bundled MCP servers**, resolved from `.factory/config.json` (roles `pmo` / `git` / `docs` → providers; credentials in `.factory/.env`, never committed). The **git** role accepts `azure-devops` | `github` | `gitlab` | `bitbucket`; **PMO** accepts `jira` | `azure-devops` | `github` | `gitlab`; **docs** accepts `confluence` | `azure-devops` (Wiki). One resource can back several roles (e.g. `github` for PRs + Issues; `azure-devops` for PRs + work items + Wiki). Use the MCP for the role a task needs — *which/when* is configured here; the *how* (tool names) comes from the servers themselves. This project wires **git → GitHub only**; PMO and docs are unused.
